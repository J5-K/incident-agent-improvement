# Vue 최종 검증 — 개선 전·후 비교

검증일: 2026-10-20. 코드: `f3836e2`. 실제 Vue(http://localhost:8600/)에서 질문마다 화면 새로고침으로 독립 대화를 생성하여 순차 실행했다. Ollama qwen3:0.6b / qwen3:8b, v2 서버를 최신 코드로 재시작했다. SQLite DB는 삭제하지 않았다.

## 저장 구성

- `before/`: 기존 개선 전 캡처와 기록을 복사한 원본 증거. 이번에 재실행한 결과가 아니다.
- `after/`: 실제 개선 후 최종 답변 캡처 10개, 긴 답변의 실행과정 보조 캡처 2개, 질문별 화면 텍스트 10개, JSON 기록과 CSV 결과표.
- 캡처는 실제 브라우저 화면이다. 긴 채팅은 스크롤로 일부가 가려지므로 06·08은 실행과정 캡처와 최종답변 캡처를 함께 본다. 화면 텍스트 기록은 전체 표시 내용을 보완한다.

## 핵심 개선 비교

| 질문 | 개선 전 | 개선 후 실측 관찰 |
|---|---|---|
| 02 일상 CPU 표현 | 일반 대화로 오분류 | 모니터링과 cpu-spike 매뉴얼 조회, 최종 답변 |

최종 답변 완료: **10/10**. 정의된 경로·조회 대상·매뉴얼 연결 확인: **10/10**. 이는 수치·원인·조치의 의미적 정확도가 100%라는 뜻이 아니다. 개선 전 전체 정확도나 속도 비교를 위한 동일 조건 측정은 없으므로 정확도 증가율·속도 개선율은 계산하지 않는다.

## 남아 있는 답변 품질 문제

- **06: 명확한 수치 판단 오류.** 현재 CPU 88.4%를 “90% 초과로 판단”이라고 답했다. 조사 대상 누락은 해결됐지만 수치·조건 검증은 부족하다. 전체 답변 정확성은 통과로 보지 않는다.
- **04: 조치 조건 해석 오류.** 메모리 88.8%에서 90% 이상일 때 수행할 재시작을 즉시 수행하도록 기술했다.
- **02:** 현재 CPU 88.4%와 샘플 알림 91%의 차이를 충분히 설명하지 않았고, 일부 runbook 단계 인용이 정확하지 않다.
- **10:** 일반 대화는 정상 경로이나 “빠르게 비서”라는 어색한 표현이 있다.
- UI의 “검수 통과”는 현재 코드의 길이·번호 형식·대상 이름 확인이다. 수치/조건/원인의 정확성을 검증했다는 의미가 아니다.

모니터링은 실제 운영 시스템이 아닌 샘플 데이터이고 수치에 무작위 변동이 있다. 경고 문자열은 고정되어 현재 수치와 다를 수 있다. 이번 검증에서는 코드를 추가 수정하지 않고 관찰 결과를 보존했다.

## 기록 기준

초기 서버 전환 과정에서 Ollama 연결 실패가 한 번 발생했다. 로컬 Ollama를 재시작하고 새 대화에서 01번부터 다시 실행했다. after에는 복구 후 완료된 최종 실행을 저장했다. 수동 대기·캡처 시간이 포함되므로 응답 속도 지표는 보고하지 않는다. 개별 질문의 상세 내용은 `after/테스트결과표.csv`와 `after/화면기록.json`을 참고한다.
