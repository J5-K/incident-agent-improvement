# 수치·조치 조건 검증

AI의 자유 서술을 최종 권고로 사용하지 않고 출처 ID·매뉴얼 단계·조건 상태·원인 가설 코드로 구성한 JSON을 받는다. Python이 수치를 직접 출력하므로 모델이 “88.4는 90 초과” 같은 문장을 최종 답변으로 생성할 수 없다. 모델 출력에 수치/자유 필드를 추가해도 반려한다.

- CPU 증설: `cpu_percent > 90`. 90은 미충족. 90 초과여도 **지속 여부 미수집**이면 추가 확인 전 보류.
- 메모리 재시작: `memory_percent >= 90`. 90은 수치 조건 충족. 이는 실행 승인이나 실제 재시작을 뜻하지 않는다.
- 현재 수치와 고정 경고 문구를 분리한다. 경고의 CPU 91%를 현재 CPU 수치로 쓰지 않는다.
- 필요한 수치가 없거나 숫자가 아니거나 NaN/무한대이면 판단 불가.
- 검토된 두 정책의 원문 SHA-256을 저장한다. 원문이 바뀌면 자동 적용하지 않고 정책 재검토를 요구한다.
- 기타 단계의 조건은 자동 승인하지 않는다. 매뉴얼 원문 조건과 운영자 확인이 필요하다.
- 최대 3회 검증 반려 후 **강제 통과 제거**. AI 제안은 제외하고 관측 사실과 매뉴얼 제목만 제공한다.
- 미검증 JSON/초안 토큰은 채팅 답변으로 스트리밍하지 않는다. 조사/검증 진행 이벤트와 최종 답변은 SSE로 제공한다.

원인 코드는 고정된 가설 표현으로 출력한다. 의미적 원인 정확성을 자동 보증하거나 LLM-as-a-Judge를 구현한 것은 아니다. v2만 변경하며 v1은 기존 교육용 흐름이다.

전체 테스트 38개 통과. 실제 Ollama가 계약 JSON을 안정적으로 선택하는지는 실모델 검증이 별도로 필요하다.
