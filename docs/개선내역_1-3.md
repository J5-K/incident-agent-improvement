# 이번 요청의 기능별 변경

## 1. 수치·조치 조건 검증 (`26eec66`)

- `agent/evidence.py`: 신뢰할 수 있는 수집 출처 인덱스, JSON 제안 계약, 시스템·출처·매뉴얼 단계·조건 상태 대조.
- `data/action_policies.json`: CPU `>90`, 메모리 `>=90`과 원문 SHA-256. 변경된 문서의 조건을 조용히 재사용하지 않는다.
- `agent/graph.py`: 수집 시 출처·URI·서버 부착, 미검증 초안 스트리밍 제거, 최대 3회 후 실패를 명시하고 사실만 제공.
- `agent/{fake,ollama,openai}_llm.py`: 생성 자유 문장을 출처·단계·가설 코드 선택으로 변경. 공개 write 인터페이스는 유지.
- 기존 04·06번처럼 잘못된 비교 문장을 통과시키지 않는다. 미충족 조치는 보류, CPU 지속 여부 미수집도 추가 확인.

## 2. 근거 보고서 (`4d518cb`)

- `agent/reporting.py`: 관측 사실 / 원인 추정 / 조건부 조치 / Tool·Resource 출처를 구분한 구조화 데이터와 표시 텍스트.
- 수치는 수집 데이터에서 직접 출력하고 원본 경고는 별도 표시. 원인 가설은 미확정으로 표시.
- `server.py`: POST 응답 metadata에 검증 여부·반려 사유·구조화 report 추가.
- `web_chat.html`: 검증 범위와 실패 상태, 출처 수·작성 횟수 표시. SSE 최종 답변은 보고서로 제공.

## 3. 고정 데이터 자동 평가 및 결과물 정리

- `evaluation/fixtures.json`: 질문 10개 + 경계값 2개 + 오류 초안 2개 + 도구 실패 1개. 지표·매뉴얼을 한 파일에 고정.
- `evaluation/run.py`: git archive로 버전을 격리해 같은 fixture를 실행. 경로·대상·시스템별 매뉴얼·구조화 수치·오류 초안 노출·도구 실패와 실행 시간 기록.
- `docs/evaluation/`: 버전별 원본 결과 JSON, comparison JSON/CSV, 판정 정의와 한계 설명.
- README, 기존 설계 문서, 검증 요약, before/after 버전 안내를 현재 상태와 일치하도록 정리.
- 기존 스크린샷과 관측 원본은 덮어쓰지 않는다. 변경 후 실모델 결과는 after/v2_grounded에 별도 보관.

## 설명할 때 구분할 점

네트워크 없는 테스트 46개 통과와 실제 Ollama 검증은 서로 다른 증거다. 고정 데이터 평가는 LLM 자체의 의미 정확도나 실제 서버 처리량을 보장하지 않는다. RAG·LLM-as-a-Judge·부분 실패 복구는 추가하지 않았다. 기본 기능은 제공 코드와 직접 수정한 기능을 구분한다.
