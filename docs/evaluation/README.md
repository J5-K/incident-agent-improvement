# 고정 데이터 자동 평가

동일 질문·고정 지표·고정 매뉴얼로 그래프를 실행했다. 실제 MCP/LLM/네트워크는 사용하지 않는다.
실행 시간은 fake/mock 및 그래프 내 교육용 지연을 포함하며 실제 모델 지연/서비스 성능 비교가 아니다.
버전별 fake 작성기는 계약 변경에 맞춘 테스트 더블이므로 LLM 정확도 향상 수치로 사용할 수 없다.
원래 기준(2c2973d), 앞선 개선 후(f3836e2), 새 개선 버전을 구분한다.

| 버전 | 경로 일치 | 대상 집합 일치 | 시스템별 매뉴얼 일치 | 구조화 수치 일치(대상 수) | 주입 오류 노출 |
|---|---:|---:|---:|---:|---:|
| 2c2973d (2c2973d) | 42.9% | 14.3% | 0.0% | 미측정 (0) | 100.0% |
| f3836e2 (f3836e2) | 92.9% | 92.9% | 91.7% | 미측정 (0) | 100.0% |
| HEAD (4d518cb) | 92.9% | 92.9% | 91.7% | 100.0% (11) | 0.0% |

수치 일치는 구조화 보고서의 CPU/메모리 필드와 fixture의 정확한 일치를 확인한다. 기존 자유 문장 버전은 미측정이며 0점으로 처리하지 않는다.
매뉴얼 일치는 시스템별 출처 연결까지 요구한다. 구버전에 연결 정보가 없으면 불일치로 기록한다. 의미 검색 정확도/recall을 측정한 것이 아니다.
13·14는 명백히 틀린 초안을 강제 주입하여 최종 응답에 잘못된 문장이 그대로 노출되는지 확인한다.
15 도구 실패는 현재도 요청 전체가 실패한다. 실패를 관측했다는 의미이며 부분 실패 응답/복구 구현을 뜻하지 않는다.
10개 기본 시나리오 + CPU/메모리 경계 2개 + 오류 초안 2개 + 도구 실패 1개 = 15개. 오류 예외는 결과 JSON에 저장한다.
판정은 시스템 동작의 회귀 검사이며 원인 추정의 진실성·실제 운영 조치 안전성은 평가하지 않는다.

현재 보고서에서 HEAD는 실행 당시 `4d518cb`이며 각 JSON 내부의 전체 commit을 기준으로 버전을 확인한다.
새 버전의 05번은 fake 라우터가 공간 부족 표현을 chat으로 분류해 경로/대상/매뉴얼 지표에서 실패했다. 실제 Ollama의 이전 05번 성공과 별개인 회귀 테스트 결과다.

재실행: 프로젝트 루트에서 `.venv/bin/python3 evaluation/run.py --refs 2c2973d f3836e2 HEAD`를 실행한다. 결과를 다시 생성하면 HEAD의 전체 commit과 fixture SHA가 새로 기록된다.
