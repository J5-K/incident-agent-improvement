- 수치·조치 조건을 Python이 계산하고 AI 출력은 출처·단계·조건·원인 가설 코드 계약으로 제한했다.
- 사실 / 추정 / 조건부 조치 / 참고 출처 보고서로 변경했다.

- 단위·그래프·보고서·평가 집계 **46개 테스트 통과**.

## 증거를 읽는 순서

1. `before/` 또는 `baseline/`: 개선 전 캡처 10개, 기준 `2c2973d`.
2. `after/1차검증_결과요약.md`: `f3836e2` 기준 10개 실제 Vue 완료 결과와 04·06번 오류 발견. 최상위 after 캡처·JSON·CSV는 이 버전의 원본이다.
3. `after/v2_grounded/`: `4d518cb` 기준 수치 조건/근거 보고서 변경 후 04·06 실제 Ollama 재검증.
4. `evaluation/README.md`: 동일 고정 데이터 15개를 Git 버전별로 실행한 네트워크 없는 자동 평가. 실제 모델 속도·정확도와 구분한다.

## 실제 Ollama/Vue 재검증

04번: 메모리 90.8%, 1회 작성 검증 통과. >=90 수치 조건 충족과 운영자 승인 필요를 구분했다.
06번: payments CPU 90.3%, 첫 반려 후 2회 작성 통과. 수치는 >90이지만 지속 여부 미수집이어서 조치 보류라고 보고했다. gateway/payments의 지표·매뉴얼 4개 출처를 각각 표시했다.

이번 재검증은 04·06 두 개다. 전체 질문 10개의 최신 실모델 정확도가 100%라고 주장하지 않는다. 캡처 당시 무작위 수치와 고정 평가의 88.4/88.8은 다른 실행이다.

## 고정 데이터 자동 평가

세 버전: 원래 기준 `2c2973d`, 기존 개선 `f3836e2`, 새 보고서 그래프 `4d518cb`(결과 파일 HEAD.json 내부 commit에 기록).

- 고정 시나리오 15개: 기존 질문 10개, 경계값 2개, 명백한 오류 초안 주입 2개, 도구 실패 1개.
- f3836e2 대비 오류 초안 노출: **2/2 → 0/2**. “88.4%를 90% 초과”, “88.8%가 90% 이상”이라는 잘못된 생성 제안을 새 버전은 반려 후 최종 답변에서 제외했다.
- 새 구조화 보고서 11개에서 CPU·메모리 필드가 fixture와 일치. 기존 자유 문장 버전은 같은 구조화 지표를 측정할 수 없어 미측정이며 0점으로 간주하지 않는다.
- 새 버전 경로/대상 일치 13/14, 시스템별 매뉴얼 연결 11/12. fake 라우터가 05번의 저장 공간 부족 표현을 chat으로 분류하는 한계를 그대로 기록했다. 앞선 실모델 05번은 정상 조사였으며 서로 다른 평가다.
- 응답 완료 14/15: 15번 도구 실패 주입은 예외를 관측했다. **부분 실패 응답은 아직 구현하지 않았다.**
- 실행 시간은 스텁 호출과 교육용 지연을 포함하며 실제 Ollama 응답시간 개선 지표가 아니다.

## 남은 한계

검토한 수치 정책은 CPU 증설/메모리 재시작 2개다. CPU 지속 여부·배포 시점 등은 미수집이므로 추가 확인을 요구한다. 매뉴얼 원문 해시가 바뀌면 해당 정책은 판단 불가로 전환한다. 원인 가설은 가능성으로 표시하며 진실성을 보증하지 않는다. 매뉴얼 선택은 기존 키워드 방식이며 RAG·LLM-as-a-Judge·부분 실패 복구·비동기 LLM 전환은 추가하지 않았다.
