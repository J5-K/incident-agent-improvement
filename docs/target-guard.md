# 개선 1: 미등록 시스템 임의 대체 방지

## 문제와 변경

기준 사례 09는 billing-service를 요청했지만 auth-service의 수치를 사용했다. v2 그래프 진입점에 target_check를 추가했다. 미등록 이름이 있으면 LLM/MCP를 호출하지 않고 확인 안내로 종료한다. 이름 없는 장애 요청도 라우팅 후 확인 안내를 반환한다. 일반 대화와 등록 시스템 조사 경로는 유지한다.

`agent/targets.py`는 monitoring.json의 등록 목록과 명시된 이름을 경계·대소문자를 고려해 비교한다. 기본 시스템을 반환하지 않는다. graph의 MCP Prompt 대상 추출도 유효한 이름이 없으면 실패하도록 바꿨다. Vue에는 확인 안내 단계 표시를 추가했다.

## 범위와 한계

- 기본 v2 그래프에 적용. v1은 개선 전 legacy 비교용으로 유지한다.
- 미등록 이름과 등록 이름이 섞이면 부분 조사하지 않고 전체 확인을 요청한다. 안전성 대신 사용자의 추가 입력이 필요하다.
- 별칭, 자연어 시스템명, 대명사·이전 대화의 대상 복원은 지원하지 않는다. 이름 없는 incident는 재질문한다.
- `-service`/`_service` 또는 `web-01` 형태의 이름과 등록 목록의 정확한 이름을 검사한다. 모든 미등록 이름 표기법을 인식하는 것은 아니다.
- 등록 목록은 그래프 모듈 로드 시 읽는다. 목록 변경 후 서버를 재시작한다.
- 복수 시스템 누락은 후속 개선 `multi-target.md`에서 보완했다. 장애 표현 오분류는 다음 단계다.

## 검증

```bash
LANGCHAIN_TRACING_V2=false LANGSMITH_TRACING=false .venv/bin/python3 -m unittest discover -s tests -v
```

네트워크 호출 없이 이름 추출, 미등록·혼합·대상 누락 차단, 일반 대화, 기존 조사 경로, 스트림 최종 응답을 검사한다. mock 검증은 실제 Ollama 응답 품질 검증과 별개다.

Vue 확인: 서버를 재시작하고 새로고침한 뒤 `billing-service 응답이 느려요. 원인 확인해주세요.`를 보낸다. 미등록 안내가 나오고 auth-service 모니터링 단계가 없어야 한다. 실행 중인 사용자의 서버는 자동 재시작하지 않았다.
