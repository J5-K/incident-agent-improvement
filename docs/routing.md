# 개선 3: 일상적인 장애 표현 분류 보완

기존 질문 02의 “프로세서가 계속 바쁘고 처리가 밀려요”가 chat으로 분류되는 문제를 보완한다.
모델이 chat으로 판단했더라도 등록된 시스템 이름과 증상/상태 조회 표현이 함께 있으면 incident로 승격한다.
원래 모델 분류와 보정 이유는 RouteDecided 이벤트에 남긴다. 모델 사용 비용도 그대로 누적한다.

전체 자동 테스트 28개 통과(네트워크 없는 fake/mock 기반).

## 검증과 한계

증상 표현, 인사/시스템 이름만 언급/개념 질문, 기존 incident 유지, 비용 및 보정 이벤트를 자동 검증한다.
기존 그래프 통합 테스트도 질문 02의 표현으로 실행하여 실제 조사 경로 진입을 검증한다.
정규식 기반 보완이므로 새로운 동의어와 부정문·인용문을 완벽하게 이해하지 못한다.
개념 표현은 보정을 생략하며 원래 모델 판단을 유지한다. 이름 없는 chat 오분류는 보정하지 않는다.
v2에만 적용한다. 실제 Ollama 응답 품질과 Vue 캡처는 아직 검증하지 않았다.

## 최종 비교 순서

서버 재시작 후 baseline/테스트질문10개.json과 같은 질문으로 테스트한다.
독립 질문은 화면을 새로고침하여 새 대화로 시작한다. 최종 답변까지 기다린 후
질문·실행 과정·최종 답변이 함께 보이게 캡처한다. 02는 조사 경로 진입,
08은 두 시스템과 각각의 매뉴얼, 09는 미등록 안내와 대체 조회 없음이 핵심이다.
캡처 전후 수치 차이는 샘플 데이터의 무작위 변동일 수 있으며 정확도 개선의 근거로 쓰지 않는다.
