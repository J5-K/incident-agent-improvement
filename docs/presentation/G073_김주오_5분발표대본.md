과제 1을 선택했습니다. 제공된 에이전트의 조사 대상과 복합 증상 검색을 보완하고, 근거와 조건을 확인하는 보고서를 만들었습니다. 실제 조치는 실행하지 않고 운영자의 판단을 돕습니다. 기반은 FastAPI, Vue, MCP, LangGraph와 LangSmith이며 제가 개선한 범위를 구분해서 설명하겠습니다.

## 2. 직접 추가·수정한 기능 (25초)

대상이 없거나 등록되지 않은 경우 다른 서비스로 대신 조회하지 않습니다. 여러 시스템의 조사 계획을 보완하고 작업 일부가 실패해도 확보한 자료를 유지합니다. 런북 검색, 내용 검증, 보고서 화면을 추가·개선했습니다. 기존 Graph 노드는 역할별 파일로 분리했으며 새로운 전문 멀티 에이전트 서브그래프를 만들었다는 의미는 아닙니다.
출처: agent/targets.py, agent/planning.py, agent/nodes/research.py, agent/runbook_search.py, web_chat.html

## 3. CPU·메모리 복합 질문 결과 (40초)

같은 시스템에서 CPU와 메모리를 함께 물었습니다. 진행 기록과 상세 근거에서 cpu-spike와 memory-leak가 모두 선택됐습니다. 이번 캡처의 현재 CPU는 90.1%, 메모리는 54.5%입니다. CPU 조건도 지속 여부를 수집하지 못해 추가 확인이 필요하고, 메모리는 90% 조건에 미달해 조치를 보류합니다. 이것은 대표 사례의 결과이며 전체 검색 정확도나 원인 확정을 뜻하지 않습니다.
출처: docs/presentation/captures/01_화면내용.txt, 02_화면내용.txt
캡처: 01_복합증상_요약.png의 보고서 부분만 확대. 원본 전체와 검색 근거는 captures/에 별도 보관.

## 4. TLS 질문의 조사 한계 안내 (30초)

사용자가 CPU·메모리·응답 지연 대응을 제외하고 TLS 인증서 만료를 물었습니다. 현재 도구와 6개 매뉴얼로 인증서 만료를 확인할 수 없어서 적합한 매뉴얼 없음으로 처리하고 AI 제안 생성을 생략했습니다. 관련 없는 지연 매뉴얼로 대신 답하지 않습니다. 화면은 요약을 먼저 보여주고 근거는 펼쳐 볼 수 있습니다.
출처: docs/presentation/captures/03_화면내용.txt
캡처: 03_TLS_확인불가.png의 보고서 부분 확대

## 5. Agent Graph와 공통 데이터 (45초)

graph.py에서 build_graph를 보여줍니다. add_edge는 다음에 실행할 노드를 연결합니다. 조사 결과가 부족하면 런북 조회로 돌아가고, 답변 검증에 실패하면 최대 세 번까지 재작성합니다. state는 이번 질문의 기록장이고 deps는 모델·MCP·검색기를 담은 공통 도구 상자입니다. 제공된 의존성 주입 구조에 검색기를 추가했습니다. 노드 구현을 nodes 폴더로 옮겨 graph.py에는 연결과 분기를 남겼습니다.
코드: agent/graph.py:35, agent/state.py, agent/deps.py

## 6. MCP 조회와 부분 실패 처리 (40초)

research.py의 research_node를 보여줍니다. MCP Tool get_monitoring_status로 상태를 조회하고, Resource로 런북 원문을 가져옵니다. 계획 단계에서는 MCP Prompt로 조사 절차를 받습니다. 아래 gather의 return_exceptions=True를 통해 작업별 실패를 수집하고 성공 결과를 보존합니다. 이후 실패·매뉴얼 부족 시 사실과 한계를 보고합니다. MCP 내부 잠금 때문에 모든 실제 호출이 완전히 병렬로 실행된다는 뜻은 아닙니다.
코드: agent/nodes/research.py:28, agent/nodes/planning.py, agent/mcp_client.py, mcp_server.py

## 7. 증상별 RAG 검색과 범위 제한 (60초)

runbook_search.py의 search_request를 보여줍니다. 질문의 증상과 제외 범위를 표현 규칙으로 나눕니다. CPU·메모리를 각각 임베딩 검색하고 기준을 통과한 문서만 합칩니다. 여기서 TOPICS는 범위 해석과 검색 문장을 보조하는 규칙이며 문서를 강제로 선택하는 폴백이 아닙니다. 질문과 문서를 정규화 벡터로 바꾸고 유사도를 계산합니다. 개별 검색 최대 두 개, 최소 0.43, 최고 점수와 0.08 차이 이내 조건을 사용합니다. 명시한 증상이 빠지면 사실 보고서로 제한하고, TLS처럼 미지원 요청도 다른 런북으로 대체하지 않습니다. 검색한 원문은 AI 초안의 근거 입력으로 전달합니다. 복잡한 포함·제외 표현과 새로운 증상은 추가 평가가 필요합니다.
코드: agent/runbook_search.py:85, 159, 173, 179; agent/nodes/research.py:118
